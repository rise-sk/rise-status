# rise-status

Public uptime checks and a status page for rise.sk, built on [Upptime](https://upptime.js.org). GitHub Actions checks the sites from outside our server, keeps the history in git, opens an issue when a site goes down and publishes the status page on GitHub Pages.

> **Not running yet.** The configuration is ready, but all workflows are switched off and the page at https://rise-sk.github.io/rise-status/ does not exist until they run. What is missing is listed under [Switching it on](#switching-it-on).

## Why it exists

Our own monitoring (rise-watch, Beszel, UptimeRobot) lives on or reports from rise-server. If the whole server goes down, something outside it should still notice, record it and show visitors that we know. Upptime does that for free on GitHub, with no server of its own.

## What it checks

| Name | URL | Every |
| --- | --- | --- |
| rise.sk | https://rise.sk | 5 min |
| rise.sk API health | https://rise.sk/api/health | 5 min |
| Prihlásenie (admin nástroje) | https://login.rise.sk/api/health | 5 min |

A check slower than 5 seconds counts as degraded (`maxResponseTime: 5000`). New public apps go into `.upptimerc.yml`.

## How it works

| Workflow | When | What it does |
| --- | --- | --- |
| Uptime CI | every 5 min | checks each URL, commits the result to `history/`, opens or closes an issue |
| Response Time CI | daily 23:00 UTC | records response times |
| Graphs CI, Summary CI | daily 00:00 UTC | draws `graphs/`, rewrites the table above |
| Static Site CI | daily 01:00 UTC | builds the status page into `gh-pages` |
| Updates CI, Update Template CI | daily | keep the Upptime template current |

Everything is configured in [`.upptimerc.yml`](.upptimerc.yml). Upptime is pinned to `upptime/uptime-monitor@v1.46.3` in most workflows.

## Switching it on

1. Add the repo secret `GH_PAT` (a token that may write to this repo and its issues) and `NOTIFICATION_DISCORD_WEBHOOK_URL` (channel `🚨-server-alerts`).
2. Enable the workflows in the Actions tab and run Setup CI once.
3. Turn on GitHub Pages for the `gh-pages` branch.
4. For https://status.rise.sk: a CNAME record in Cloudflare pointing to `rise-sk.github.io` and a row in `docs/dns.md` of rise-server.

This is a public repo, so its Actions minutes are free. It is the one place where we use GitHub-hosted runners: the point is to check rise-server from somewhere else.

## Repo map

| Path | What |
| --- | --- |
| `.upptimerc.yml` | sites, schedule, status page settings |
| `.github/workflows/` | the eight Upptime workflows |
| `history/` | one YAML file per site with its status history (written by Uptime CI) |
| `api/`, `graphs/` | JSON for badges and response time charts (written by the workflows) |

`history/`, `api/` and `graphs/` still hold the demo data of the Upptime template; the first runs replace it.
